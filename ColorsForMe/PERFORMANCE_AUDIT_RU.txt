Аудит нагрузки и безопасности — ColorsForMe 0.3.2
(Исторический документ: аудит выполнен для версии 0.3.2, актуальная версия аддона 0.4.6.)

ИСТОЧНИК: полный исходный код ColorsForMe v0.3.1 из предыдущего архива.

ПРОБЛЕМЫ И ИСПРАВЛЕНИЯ
1) Ранее applyAll(): полный обход сотен корневых Frame на каждую смену
   Custom Color и при загрузке Blizzard addon. Теперь выбранный цвет
   обновляет только уже найденные текстуры, без поиска.
2) Ранее OnShow на отдельных action buttons и окнах повторял
   getRegions/getChildren (глубина 8, предел 700 на каждый корень).
   Теперь сканирование один раз; последующие OnShow выходят сразу.
3) Ранее PLAYER_TARGET_CHANGED и PLAYER_FOCUS_CHANGED вызывали
   дополнительную работу независимо от обновления текстур.
   Эти подписки удалены; рамки обрабатываются при первом показе.
4) Ранее hooksecurefunc(DamageMeter.SetupSessionWindow) запускал
   applyAll() на все стандартные панели. Теперь проверяются только
   известные окна измерителя, причём только если они новые.
5) Ранее каждое применение RGB повторно вызывало SetDesaturation;
   теперь он вызывается только при первом окрашивании / после Reset.
6) Ранее в список попали портреты торговли и функциональные
   UI-Quickslot-depress/UI-Debuff-Overlays. Исключены из перекраски.
7) Ранее произвольные Textures внутри BorderFrame окрашивались
   по структурному признаку; теперь это правило ограничено NineSlice.
8) Убраны лишние выделения таблиц/повторные записи цветов при
   повторном показе известных элементов.

КАКИЕ ХУКИ ОСТАЛИСЬ
- Только безопасный OnShow известных корневых штатных панелей
  и динамических Blizzard кнопок аур, для первичного открытия.
- Один необязательный secure posthook для вновь созданного окна
  встроенного Damage Meter; без замены игрового кода.
- События ADDON_LOADED, PLAYER_LOGIN, а при необходимости
  PLAYER_REGEN_ENABLED для отложенного изменения после боя.
- Не используются UNIT_AURA, COMBAT_LOG, PLAYER_TARGET_CHANGED,
  PLAYER_FOCUS_CHANGED и любое постоянное OnUpdate в движке окраски.

ЧЕГО НЕТ
- Вмешательства в обработку боя, кнопки способностей, инвентарь,
  игровую логику, проверку доступности, cooldown, item textures.
- Переопределения Blizzard функций или фреймов.
- Сетевых вызовов, сторонних библиотек, файловых операций.
- Подмен игровых текстур и атласов. Файл ColorWheel.tga используется
  только для отдельной собственной кнопки настроек.

ПРОВЕРКА
- Синтаксис всех Lua-файлов: успешен (texlua).
- Моделируемый запуск на имитации WoW UI: успешен.
- Повторные OnShow: без новых обходов.
- Изменение цвета: без повторного сканирования и SetDesaturation.
- Состояния и портреты: тестовый макет показал отсутствие изменений.
- Reset: точно восстанавливает RGB, alpha и исходную desaturation.
- Blizzard load-on-demand: обрабатывает новый, не старые корни.
- После боя: отложенный цвет применяется.

РЕАЛЬНЫЕ FPS/FRAMETIME НЕ ИЗМЕРЯЛИСЬ: тест был вне игрового клиента.
Для надёжного вывода нужен сеанс A/B на реальном WoW Forever.
